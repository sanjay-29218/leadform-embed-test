Embed lab

Awkward but realistic places customers will paste the embed code.

  • Narrow sidebar (300px) – Form placed in a 300px sidebar next to article content, as many WordPress themes do.
  • Inside a flex row – Form is a child of a flex container with no explicit width (common in page builders). Iframes can collapse here.
  • In a popup (hidden at load) – Embed sits in a modal that is hidden when the page loads, then opened by a button. Checks the frame sizes itself once visible.
  • In a hidden tab – Embed is inside the second tab, which is hidden (display:none) at load.
  • Two embeds on one page – The same embed code pasted twice (e.g. header CTA and footer). Each frame should size and submit independently.
  • Long page + tall sticky header – 140px sticky header and a lot of content above the form. Checks scroll-to-error and where you land after submitting.
  • Dark website – A dark-themed customer site. Does the form still look intentional?
  • Right-to-left page – Host page uses dir=rtl (e.g. an Arabic-language customer site).
  • Theme CSS that styles iframes – Host CSS sets iframe{height:400px;border:4px solid;max-width:80%} like some themes and page builders do.
  • Script added after page load – Embed code injected 2s after load, like a tag manager or single-page app route change.
  • Wrong / missing form id – Embed with a typo in data-form, and one with no data-form at all. What does the visitor see?
  • Page scaled with CSS transform – Form inside a container scaled to 0.85 (seen in some site builders' mobile previews).
  • Size matrix – The same embed at 280–1440px container widths (scaled to fit). Use ?w=375,768 to pick widths.

Also: embed-test.html (any form id + message log).
